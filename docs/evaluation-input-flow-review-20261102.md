# 空白案件填寫流程修正

狀態：本機預覽完成，尚未部署。

## 查得問題與處理

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| 缺都更、容移上限卻出現停車及屋突錯誤 | 必要上限缺值進入量體與停車搜尋，原缺項訊息被後續錯誤取代 | 在網站計算入口先沿用共用計算器檢查上限，保留原輸入，阻擋缺項後再執行原計算 |
| 都更、容移上限放在地下室頁籤 | 不同工作內容混在同一展開區 | 移至基地與獎勵；依採用路徑顯示，既有輸入值保留 |
| 三個基地欄位填完就顯示資料已齊 | 狀態僅檢查基地面積、建蔽、容積率 | 狀態採整份評估的檢查結果，涵蓋地區及模式的條件項目 |
| 新空白案件尚未選過獎勵選單，仍被要求填危老 | 表單顯示都市更新，但初始輸入未建立相同路徑 | 新案件與清除後建立都市更新路徑；匯入舊案件沿用既有資料 |
| 快速目標缺項未精確聚焦 | 提示文字改用畫面欄名後，缺少相同欄名的定位比對 | 增列完整及省略單位的欄名比對 |
| 臺北都市計畫開挖條件未精確聚焦 | 對應資料只指向地下室區域 | 指向都市計畫開挖規定選單 |
| 屋突高度欄位單位旁出現直線 | 定位外框直接畫在數字輸入區，與單位區相交 | 外框改畫在包含單位的整個欄位，保留輸入游標及鍵盤焦點 |

## 文案前後

- 「基本資料已填，請核對其餘規劃條件」改為依檢查狀態顯示「尚有 N 項條件待核對」或「必填條件已填，請核對後計算」。
- 移除會自動採用50%／30%的原說明，改為要求填入本次採用上限，個案合計上限有文件依據時再填。
- 缺項文字採畫面欄名，點選後回到該欄位。

## 驗收

- 從空白案件開始，依缺項清單逐欄填寫18個欄位，18項均完成跨頁返回及實際聚焦。紀錄：`evaluation-input-flow-review-20261102/field-focus.json`。
- 臺北、新北 × 都更、危老四種模式均實際完成計算；都更模式沒有危老目標欄位，危老模式沒有都更上限欄位。臺北的兩個開挖必選項均可聚焦。紀錄：`evaluation-input-flow-review-20261102/city-route.json`。
- 板橋1600㎡、建蔽50%、容積300%、都更50%、容移25%；每戶30坪、每戶汽車需求1位、坡道平面停車。結果：可售3,810.27坪、113戶、113位汽車、地上17層、地下5層，與修正前完整輸入結果一致。
- 281項欄位、路徑及定位測試通過；42項案件檔及報告檢查、六種地區／路徑報告、107項臺北地方獎勵、67項危老面積檢查及六支舊App檢查通過。
- 6個受保護來源檔及81個非介面函式維持相同內容；建置及公開頁檢查通過。
- Safari實際點選缺項後可聚焦屋突高度，單位旁直線消除；360／390／430px無水平溢出，沿用手機介紹頁及電腦版工具限制。

## 保留的資料要求

土地與法規事實、道路資格、查證日期與來源維持個案填寫。未確認資料不填成已核定。空白值不自動視為0；不增設或不採用時，使用者須依畫面填0或選擇適用模式。計算公式、共用核心及其他工具未修改。
