# 看板名稱與說明盤點（2026-10-21）

適用範圍：總覽、全部來源類別、個別訪客、操作時間與明細、地區與內容、案件報告、AI、資料缺漏與更新失敗。沿用核准版面與配色。這次只改顯示名稱與解釋，不改統計、追蹤或資料庫紀錄。

## 來源分類完整對照

| 實際記錄 | 顯示名稱 | 可以判斷的範圍 |
| --- | --- | --- |
| 平台來源網站資訊 | 瀏覽器回報來自 X | 取得網站資訊，沒有貼文或搜尋關鍵字 |
| 網址含平台名稱 | 網址註明來自 X | 只知道網址上填的名稱；可能被轉傳 |
| 網址有來源但名稱不在支援名單 | 網址註明的來源無法辨認 | 沒保存原字串，不猜平台 |
| 其他來源網站 | 來自其他網站（未保存網站名稱） | 知道是其他網站，無法還原名稱 |
| 無可用來源資訊 | 無法知道從哪裡進站 | 不能說是直接輸入或任何平台 |
| 站內來源或跨午夜延續 | 接續站內瀏覽，最初來源不明 | 沒有原始外部進站依據 |
| 當時沒有記錄來源 | 當時沒有記錄來源 | 缺漏；不當成直接輸入 |
| 只留下平台名稱 | X（無法確認怎麼進站） | 沒有保存標記／網站判斷依據 |

平台名稱包含 Google、Facebook、Threads、Bing、Yahoo、DuckDuckGo、百度、Instagram、LINE。來源總覽與每位訪客的名稱、明細說明共用同一份定義。資料不完整的類別用橙色；已知平台仍用墨綠。

## 其他區域

| 原用語或問題 | 改善後 |
| --- | --- |
| 今日瀏覽器識別數 | 今日訪客數；說明同一瀏覽器一天計一次 |
| 累計瀏覽器日人次 | 每日訪客數加總；說明跨日分別計入 |
| 判讀與資料完整度、資料快照 | 這些數字怎麼算？哪些資料有缺漏？；各區塊在同一次更新取得 |
| 首次頁面紀錄／最後開啟頁面 | 首次開啟時間／最近開啟時間；系統收到開啟紀錄的時間 |
| 最後收到操作 | 最近操作時間；無紀錄時明確寫沒有收到操作紀錄 |
| 首次開啟頁面 | 第一個開啟的頁面 |
| 已記錄停留時間（估計） | 累計網頁顯示時間；只加總螢幕上顯示且有收到的紀錄，不是專心閱讀時間 |
| 尚未取得停留時間 | 沒有顯示時間紀錄；不當成 0 秒 |
| 部分瀏覽未取得停留時間 | 部分瀏覽缺少顯示時間 |
| 最高記錄捲動、捲動至75%以上 | 最深捲動位置、曾捲到頁面 75% 以上：X 次瀏覽；不稱讀完 |
| 未啟用操作追蹤 | 當時未記錄操作，無法判斷是否有點擊或捲動 |
| 服務／健檢點擊、聯絡點擊 | 點擊服務或健檢連結、點擊聯絡連結；不當成諮詢完成 |
| 國家與城市（估計） | 訪客地區（依網路位置估算）；國外只按國家 |
| 各地瀏覽紀錄與內容分類 | 各地訪客看過哪些內容；同一人看多項內容會在各項分別計入，不能相加當總人數 |
| 各頁面瀏覽量 | 各頁面開啟次數；文章合併到三策觀點的既有規則不變 |
| 報告累計瀏覽器識別／進入次數 | 開啟報告的訪客數／累計開啟次數；同一瀏覽器跨日只算一位報告訪客 |
| 重複開啟的瀏覽器 | 開啟兩次以上的訪客數；不稱不同時段回訪 |
| 個別訪客與進入明細 | 每位訪客的報告開啟紀錄；第一次／最近一次開啟、每次開啟日期時間 |
| 今日提問訪客 | 今日提問訪客數 |
| 待完成／狀態未確認 | 尚未確認回覆結果；沒有成功／失敗結果，不猜正在處理 |
| 每筆成功建立紀錄的請求 | 系統有留下紀錄的提問；清楚說明回覆失敗也計入、輸入不合格或未存下的不計入 |
| 提問未識別訪客 | 提問無法歸入提問人數；仍計提問次數 |
| 伺服器確認寄送 | 諮詢已交給寄送服務（不代表已送達） |
| Load failed／Timeout | 更新失敗／更新等候逾時；已顯示資料時交代保留上次成功資料 |

未知、零值、沒有啟用記錄、更新失敗分別說明；沒有來源或原始名稱的資料一律不補猜。欄位與長說明一起逐句讀回，維持上下文一致。
