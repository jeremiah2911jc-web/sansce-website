# 文章閱讀進度條定位盤點

狀態：使用者已確認預覽，於2026-10-26明確要求本輪上架。

## 原因與修正

使用者提供的手機截圖顯示銅色閱讀進度條穿過品牌與導覽。全站僅有一個閱讀進度元件：原本由DesignMotion渲染到頁首外，以fixed top:78px定位，手機另覆寫為50px。後續手機頁首已調為80px，舊值未跟著變更，造成全體文章共同錯位；桌機亦存在初始94px與捲動78px高度變化的同類風險。

將共用閱讀進度抽為ArticleReadingProgress，放入DesignHeader內，以absolute bottom:0跟隨頁首實際底緣，移除固定top。保留原銅色、桌機3px／手機2px厚度及進度計算口徑。進度條不攔截點擊，置於頁首正常層級，不跨越導覽面板。

讀取條件改依正式knowledgePages文章資料，非文章頁不渲染。進度依捲動更新，另監看正文尺寸與視窗尺寸變化，圖片延後載入及橫向切換後能重新量取正文。

## 盤點與驗證

全體19篇文章，逐篇檢查390與1440px，Chromium及WebKit皆核對文首、中段、文末及往回捲動；另以3篇代表文章檢查320、360、375、412、430、768、1280及844×390橫向。

額外將頁首測試高度改為112px，切換手機、橫向及桌機，驗證進度條跟隨實際底緣，不依靠另一組硬編碼高度。檢查全站導覽可開關，並確認首頁、文章列表、顧問服務、聯絡及危老評估沒有閱讀條。這是元件定位測試，不變更正式頁首高度。

完整檢查腳本、每筆幾何／進度數值與截圖保存在網站上一層reading-progress-audit-20261025資料夾。results.json記錄各頁／尺寸／捲動位置的頁首底緣、進度條上下緣及進度值；check.log記錄最後執行狀態。建置與SEO／路由／資產檢查另存build-reading-progress-20261025.log。

只修正文閱讀進度條及觀察時機，不修改文章定稿、照片、主題順序、頁首經文或全站助理。
