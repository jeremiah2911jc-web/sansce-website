# 三策坪效系統正式網站壓測方法

測試日期：2026-10-21（台灣時間）。使用者授權逐級壓測正式網站。

## 測試路徑與資料隔離

- 網域為 `https://www.sanzepm.com.tw`，使用正式 Vercel 專案、正式 API 處理程式及同一 Supabase 資料庫主機。
- 本次簽章請求僅將資料寫入與在線計數導向獨立測試資料表；欄位、索引、檢查限制及相關函式複製自正式版本。不將壓測人數混入正式訪客或在線人數。
- 簽章使用本次部署獨立短期金鑰，具有固定失效時間。完成後移除臨時入口，回到一般正式處理程式。
- 正式資料不回填、不刪除。每階段核對成功連入人數、獨立測試在線計數、實際儲存頁面與完成事件。

## 工作負載

1. 先由20個新工作階段下載 HTML 與正式 JavaScript/CSS（分批4個），驗證完整必要資產可取得。這一項不稱為20個同時操作中的瀏覽器。
2. 再以 HTTP 虛擬使用者依序加壓：1、25、100人。原規劃更高階段；250人階段進行中收到使用者指定100人上限，立即中止；該未完成階段不作容量結論。
3. 每階段在15秒內漸進進站；每位使用者開啟頁面、建立瀏覽紀錄，停留75秒，每15秒回報在線與顯示時間，每30秒執行有效範例計算並記錄完成事件，最後回報離開。
4. 每10秒核對測試在線人數及公開坪效頁是否正常；同時低頻讀取正式看板完整資料，觀察後台是否受影響。
5. 回報各項請求數、狀態碼、失敗數、p50/p95/p99與最大回應時間、實測最高在線數、成功連入數、計算完成數；同時記錄發壓電腦的事件迴圈延遲與記憶體，避免把發壓端瓶頸誤認為網站上限。

## 停止條件與通過條件

- 持續出現超過1%請求失敗或p95超過3秒，停止增加負載。
- 公開頁面健康檢查失敗，或發壓端超過600個未完成請求，立即停止。
- 階段須全員連入、沒有失敗、在線人數確實達到目標且監控回報p95低於3秒，才列為通過。
- 最高通過階段只代表此測試條件下已驗證的下限。沒有測出失敗點，不能宣稱已找到最大容量；不為找極限而持續壓垮有真實使用者的正式站。

## 結果的適用範圍

- 這是實際網站請求與資料庫讀寫壓測，並非開啟數千個完整可視瀏覽器；不代表數千台不同規格裝置上的版面、輸入及渲染速度都已驗收。
- 評估引擎在發壓端執行相同程式，成功才送完成事件。正式網站的公式計算原本就在各使用者電腦上，不集中占用伺服器CPU。
- 高人數階段採已取得前端資產的使用情境。20個新工作階段的資產下載檢查，不能當成已驗證數千人同秒首次下載全部資產。
- 不涵蓋多人同時向AI提問、寄送諮詢、登入案件報告或累積數月歷史資料後的看板查詢容量。
