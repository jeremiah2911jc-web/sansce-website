# 三策文章寫作與上架前盤查規則

依使用者2026年10月24日至25日明定要求，適用三策觀點全部既有文章、新文及改稿。同步規則頁：https://chatgpt.com/space/page_8387183e7c688191a92a547c06566585。

## 直接論述

先寫具體情境或明確主張，再說明事實、制度、條件、因果及對地主的影響。每段完成一個論點；不以空泛口號、浮誇比喻、抽象金句或重複立場標籤代替分析。不虛構案例、實務經驗或統計。

文章主標、小標、摘要、導言、正文、引言、圖說、圖片文字、延伸閱讀及SEO資料均禁用設問、反問、自問自答、假想讀者對話，以及中文或英文問號。禁用「怎麼」「為什麼」與句末「嗎」「呢」等對話式疑問語氣。改稿須把問題寫成有依據的判斷、條件與結果，不只刪問號或換成仍吊胃口的陳述。

## 禁用句型與詞彙

- 禁用以「自動」描述權益、資格、分配、完工、責任及推論結果，包括「自動變成」「自動取得」「自動增加」「自動完成」「自動涵蓋」「自動等於」及否定式。直接列明成立條件、程序、計算或責任。法令規定免申請時，具體寫明符合的條件與免申請事項。
- 禁用「不是……而是……」「不在……而在……」「不能只……還要……」等對照套句。
- 禁用「真正」「從來」「口徑」「對帳」；不用「往往」「其實」「很多時候」代替事實依據。
- 禁用「值得注意的是」「更重要的是」「這也提醒我們」「讓我們先思考」「值得警醒」「有一個更前面的問題」「背後還有一個問題」及同型空泛鋪陳。不用「有時候」開頭。
- 禁用「我們很容易問」「一個很深的」「整理情緒」「需要一直記得」「……長出來」等AI套語。刪除不增加意義的強調詞，依句子內容重寫，不機械套用替換詞。

## 具體動詞與評論責任（2026-10-27使用者逐段修正）

- 不用「處理」代替估價、補繳、領取、補償、終止、變更、清償、承接、補強等具體行為；正式法規及規範名稱保留原文，不機械刪除單字。
- 寫「檢驗、確認、比較、說明」時，接著列明資料、比較項目、計算方式、支付對象或負責人；不以抽象名詞堆疊代替論點。
- 刪除「有分析價值的批評」「較精準的評價」「值得承認的進度」及替文章自評的句子。直接交代事實、結果與批判依據。
- 「交換對價」「共同負擔」「差額價金」等專業名詞可保留，但須寫清楚涉及哪些財產、由誰支付、如何計算。住宅成果依實際階段寫作完工、交屋或住戶拿到新屋，不泛稱交付成果。
- 改寫範例中的問句，仍依本檔既有直接論述規則寫成陳述；政策事實與作者主張分開，不藉文字潤飾新增未查核的事實。
- 政策評論分清已知事實、未公布的條件與三策判斷，不在每次批判後加上「這是風險」「可供檢視政策方向」「仍待評估確認」等自我註解。「執行安排」「履約安排」改寫為實際承諾的預算、人力、住所、核貸及撥款日期、完工期限與延期賠償；未知的項目直接列出，不把抽象詞當作配套內容。

## 帳字套語與注意詞彙（2026-10-27）

禁用「帳算清楚」「算清楚」「算得清楚」及以「帳」比喻成本、分配、利益或責任的套語，包括「算這筆帳」「成本帳」「利益帳」「責任帳」「政治帳」「算到某人的帳上」「帳面分配」。不得只刪除禁詞，或改成「說清楚」「講清楚」「看清楚」後仍以空泛結論收尾。金額應列明成本項目、計算方式、付款人與收款人；分配應寫分回房地、補繳或領取的差額；責任應具體寫明誰辦理、支付、履行或賠償。

盤點注意詞彙：「說清楚」「講清楚」「看清楚」「釐清」「攤開」「落地」「關鍵」「核心」「本質」「配套」「推進」「銜接」「檢驗」「評估」及「安排」。遇到這些字詞，覆讀整句是否寫出行為、對象、依據與影響；沒有具體內容就重寫，不能機械換詞。帳戶、帳號、帳冊、記帳及帳面獲利等具明確財會意義的用語，仍須逐句確認其所指資料，不作為比喻套語的例外。每次上架前同步盤點主標、小標、摘要、正文、側欄、圖說、替代文字及SEO，保存命中位置、改寫內容或保留理由。

掃描將未明列的含「帳」用語列為阻擋項目，須經編輯確認實際意義；注意詞彙另列命中清單，不能將出現次數當成文章合格與否的依據。保留已具體說明對象與行為的必要用語，不用同義套話替換。

## 事實與版面

法律、政策、數字及個案事實應查核一手資料。保留已查證事實、估算假設與分析之間的區分，必要限制緊接相關主張。引用不得改變原資料的意思；來源名稱可簡潔標示其主題與日期。

不用粗體及章節序號。每個思想放在同一段，進入下一層論述才空一行；正文靠左，依欄寬自然換行。標題依完整詞組檢查換行，禁止截字或縮小掩蓋問題。

## 每次上架前的內容盤查

1. 執行 `npm run verify:article-copy`，掃描全部文章資料及圖片文字。出現禁用語即阻擋建置。
2. 逐段人工覆讀主詞、行為、依據、條件及影響，檢查問句改寫後的銜接、假想對話、空泛前導及擬人化鋪陳。掃描通過不代表語氣合格。
3. 核對改稿前後的事實、數字、引用、原發布日期及網址；修改日期如實更新。標題改動同步處理列表、首頁、搜尋、分享、相關文章與SEO資料。
4. 完成建置、來源核對及桌機／手機／Safari版面驗收，保存各篇盤查與修正紀錄，再依使用者授權上架。

## 2026-10-27 文案用詞與句型定案

本節依使用者當日逐項糾正整理，適用三策文章及網站對外文案，包含主標、小標、導言、摘要、正文、表格、側欄引言、圖說、替代文字、搜尋與分享摘要、SEO、介面說明、網站助理回答及撰稿回覆。既有文章改稿也須逐段覆讀，不能只修改使用者圈出的句子。正式法規名稱、明示的直接引文及須保留的原始紀錄不得任意改字；清楚標示其來源，不把引文例外擴大成一般文案例外。

### 禁用泛稱動詞與含糊結果

- 一般對外敘述不用「處理」及「獲得處理」「後續處理」「處理工具」「處理窗口」代替具體行為。依情境寫估價、補繳、領取、補償、終止契約、變更信託、清償債務、承接工程、補強、修繕、安排住所、受理爭議、協調及答覆。正式名稱「臺北市中繼住宅申請處理原則」保留。
- 「須、應、確認、評估、檢驗、比較、說明」不能單獨當成整段結論。保留時，寫明查哪份資料、比較哪些項目、如何計算、誰支付、誰負責，以及何時完成；不為消除字面重複而換成另一個籠統動詞。
- 不用「逐項算清楚」「利益如何實現」「完成多少戶」「後續交付結果」「交付成果」籠統統攝不同工作。錢寫金額與支付對象；分配寫房地內容與補款；住宅成果寫已開工、已完工或已交屋的戶數，標明階段與統計範圍。
- 不用「案件推進」「行政承接能力」「新增服務量已獲充分支應」「房源與資金須接續」作為完成說明。直接列出完成整合、取得核貸、實際開工、承辦人數、委外件數、下一批住宅的位置、出資者及完工日期。

### 禁用抽象名詞堆疊與不自然搭配

- 「執行安排」「履約安排」「融資銜接」「可行的辦理方法」「相應的經費與進度管理」「可查核的執行內容」改寫為承諾的具體工作：預算、人力、受理機關、申請資格、核貸金額、撥款日期、住所、完工期限、延期賠償及違約責任。依該段需要列出，不在每段重複同一份清單。
- 不用「建立公平且可執行的交換安排」「作出有內容的承諾」「政策企圖」「居民的決策處境」「淨分配」「市場承作意願」「面積包含範圍」要求讀者自行猜測。分別寫換屋估價、差額由誰負擔、居民同意的條件、政策目標、家庭財力與居住需要、地主分回的房地、是否有建商或出資者承接，以及坪數是否含公設、陽台與車位。
- 「交換對價」「共同負擔」「差額價金」保留其專業意義，接著交代財產、計算基礎及支付方向。金額與面積不可直接加減；面積、價值、費用及權利種類須分開。
- 「都更意願高、分配方案接受度低，可以同時存在」不作抽象總結。直接寫「地主願意重建，仍可能不接受現有的分配方案」，再說明補款、室內面積或搬遷住所等原因。

### 禁用文章自評與反覆自我註解

- 刪除「是有分析價值的批評」「較精準的評價是」「這是值得承認的進度」「這些制度應納入評價」「這些資料支持對其執行基礎的肯定」「必須承受同等嚴格的檢驗」等自評句。直接寫已完成的事實、未解決的問題與判斷依據。
- 不反覆用「這是風險」「草案內容可供檢視政策方向」「仍須透過後續方案及評估資料確認」沖淡前段論點。事實、尚缺的資料及作者判斷各自寫明；保留必要條件與推論標示，不為語氣尖銳而把未知當成事實。
- 不用「只比較名稱」「而非不斷猜測下一次選舉」等空泛對照收尾。直接交代服務範圍、人力、完成期限或規則的適用日期。

### 實績、承諾與責任必須分開

- 現任者已完成的成果，與新方案承諾的做法分句陳述，主詞具名。不能將「完成多少戶、誰出資、分回多少」列在一起，再用「兩人的承諾都得算清楚」收束。
- 分開已施行制度、規劃公告、預算案、法定預算、草案與訪談構想。申請、核定、招商、開工、完工、交屋各有不同結果，不以其中一項代稱全部完成。
- 批判要接上具體影響與責任：宣傳坪數高於個案試算，可能引發何種分配爭議；延誤後誰協調、誰支付增加的租金及利息；無法履約時如何終止、賠償與接手。不推定未公開資料等於沒有研究或無意履行。
- 小標直接呈現該節判斷，避免整篇套用「事項＋須＋動作」。使用者建議中的問句仍依既有規則改成陳述，不只刪問號。

### 每次改稿的人工盤點欄位

逐段核對：主詞是否清楚、動詞是否具體、受詞是否完整、數字所指階段是否明確、事實與承諾是否混寫、責任與費用是否有對象、必要限制是否緊接主張、是否重複自評或免責。同步覆核導言、摘要、目錄、側欄、圖說、表格及SEO；保存修正前後對照。既有禁用語掃描繼續執行，以上語意檢查不能以掃描通過代替。
